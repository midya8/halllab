# Local is not joint: overlapping all-different scopes

[Live overlapping inspector](https://midya8.github.io/halllab/overlaps.html). [Original method and six-source ledger](METHOD.md) remain unchanged. New native API `halllab.overlap.overlaps(data)` and `verify_overlaps(report)`; separate module CLI `python -m halllab.overlap input.json --output report.json`, then `python -m halllab.overlap report.json --verify`. Base single-constraint v1 API/report/tests are preserved byte-for-byte.

## Contract

Exactly `values`, `domains`, `scopes`. Domains retain original type/order/cap rules (six variables, eight values). Up to six distinct scopes, each a strictly increasing list of original variable indices; empty scopes and no scopes permitted. All scopes are all-different, not a single all-different over all variables. Unscoped variables are unrestricted by scopes and may repeat values. Every full assignment must still choose a value for every variable, including unscoped ones.

Each synchronous round contains current `domains`, all per-scope original `halllab-v1` reports in input order, and `next_domains`. Map a local report's variable position j through `scopes[k][j]` to the original variable. All scopes see the same current snapshot; intersect their retained values for each original variable to form next domains. Unscoped variables stay unchanged. Continue until unchanged; include exactly one terminal unchanged round, not an extra repeated round. At most 49 rounds (48 possible value removals plus one stable evaluation). This is complete local generalized arc consistency to fixed point, not a deliberately weak/stopped baseline.

`local_domains` is the fixed point. `local_consistent` means every original variable has a nonempty fixed-point domain and every scope's final relation is satisfiable. The explicit all-domain check catches an unscoped empty domain even when every actual scope is satisfiable. Empty scope and empty problem both have one empty tuple; no scopes admits all Cartesian assignments, including repeated values. An empty domain gives no full tuple.

Joint oracle enumerates **original** full Cartesian assignments, not partial matchings or only fixed-point tuples. A tuple is accepted iff every input scope sees distinct values. `solution_count` and `satisfiable` refer to that joint relation. Each `edges` record has original variable/value, whether local fixed point retains it, joint supported status and first lexicographically ordered full common assignment (or null). `global_domains` are exact common-support projections. Global values are always a subset of locally retained values; local viability alone proves neither satisfiability nor global support completeness.

`rejection_counts[k]` counts original full tuples whose **first** violated scope is k in input order. These bins plus accepted count partition the Cartesian product. Scope reordering changes attribution bins, not the relation. Zero bin is not an irrelevance proof. Bins are not compact logical refutations or Hall obstructions. A network can have no common assignment even though no single original-scope Hall deficiency exists. Joint failure is audited by exhaustive enumeration, not presented as a short whole-network certificate.

Top-level `halllab-overlaps-v1` keys: schema,input,rounds,local_domains,local_consistent,satisfiable,solution_count,rejection_counts,global_domains,edges. Original single-scope v1 embedded reports retain their exact contract.

## Independent execution and checks

Native propagation calls original augmenting-path/bitmask single-scope generator. Native joint generation expands full tuple prefixes iteratively, tests distinctness via scope sets and records first supported edge tuples. Checker does not call overlaps/analyze/joint. It runs the original independent single-scope checker on each embedded report, separately enumerates each local relation to form simultaneous intersections, requires the terminal stable snapshot, then separately uses itertools.product and pairwise equalities per scope to replay original joint assignments and rejection bins. Strict nested type/key/order checking rejects booleans as indices/counts, missing/extra rounds, wrong local inputs/next domains, reordered records and forged supports. Tests disable all three generator entry points while verifying.

JavaScript uses the original independent local assignment tree engine, separately enumerates joint assignments recursively and stores first support in a map. No native output at runtime. Full report cross-checks include every embedded old report, all round domains and all joint records. Existing 12 native/three Node/Chrome original test sources remain byte-identical; eight new native tests and three new Node/Chrome tests.

Native extension tests enumerate all three-variable/two-value domain graphs with every subset of the three pair scopes (64 domain combinations × 8 scope networks = 512 inputs), plus all 512 three-variable/three-value triangle domain graphs and 100 seeded larger inputs. Nine controls include two-color impossible triangle, satisfiable locally-incomplete triangle, same relation as one global scope, cross-scope cascade, unscoped repeated values/empty domain, no scopes, empty tuple and maximum 262144-tuple family. New complete Python/JS comparisons cover 621 reports, 1166 rounds, 2326 local reports, 2109 original edges, 289 locally retained but jointly unsupported edge records and 262781 accepted tuples summed across fixtures. Actual Chrome inspects nine controls, 89 original edges (12 locally-only), 13 rounds, 23 scope reports and all 79 current local-edge records, at every 320/390/1280 width; exact table/common witness/local mapping/obstruction/rejection bins/JSON/export/stale clearing/no overflow.

Installed reproduction retains original ten controls/both entry points, adds nine overlap controls through module CLI generation/verification outside checkout and checks fourth installed module origin. Python 3.10-3.13 and Node/Chrome CI retained. Native strict JSON/atomic output/byte limits inherited through CLI helper injection, without changing its original defaults. Browser JSON.parse retains last-key-wins and its existing lexical-number/byte-cap differences. Maximum original Cartesian family is 8^6=262144; native joint generation stores tuples, so this bound is not a memory/performance promise for larger inputs. Local checker can enumerate partial tuples as described by original method. No optimized worklist, backtracking solver, search heuristic, production CP engine, scalability benchmark, learned model or novel algorithm.

## Sources and distinctions

Original six-source ledger remains in METHOD.md. Three additional fetched sources inspected November 9, 2026:

- Willem-Jan van Hoeve, **The alldifferent constraint: A survey**, expanded academic survey. https://www.andrew.cmu.edu/user/vanhoeve/papers/alldiff.pdf. Inspected Section 2.1 definitions of CSP/solution, Section 2.1.2 propagation to local fixed point, Definitions 2/3/6, and Section 3 decomposition comparison. Explicit statement that local means individually consistent constraints, not a globally consistent CSP, governs this increment. Our fixed synchronous snapshots are an original audit presentation, not its implementation or performance result.
- University of Glasgow, **The All Different Constraint**, academic teaching slides. https://www.dcs.gla.ac.uk/~pat/cpM/slides/all-different.pdf. Inspected the two-color three-variable pairwise example and local-vs-global-support definitions, plus Hall filtering overview. Used only classic semantics; controls/code/presentation are original. No Choco behavior/performance claimed.
- UBC, **Arc Consistency in CSPs**, academic lecture notes. https://www.cs.ubc.ca/~mack/CS322/lectures/3-CSP3.pdf. Inspected repeated revision after domain changes and three terminal AC outcomes: singleton solution, empty-domain contradiction, or remaining uncertainty. Supports not claiming fixed point as a common solution. Our generalized all-different scope oracle is stronger than binary AC per scope when scope size exceeds two; no conflation with path/strong consistency.

The triangle examples are elementary instances of classic consistency failures, not novel discoveries. Single global scope and three pair scopes have the same joint relation in the triangle control but different propagation strengths; both run fully to their own fixed points. These are descriptive exact counterexamples, not causal empirical solver-performance comparisons.
